# 議事録: ECサイト ショッピングカート機能改善ミーティング

カートリセット機能の追加に伴う仕様策定・タスク一覧

## 1. 開催概要

- **日時:** 2026年10月6日 15:00 - 16:00
- **場所:** オンライン (Google Meet)
- **参加者:** 山田（PO）、佐藤（FE Dev）、鈴木（BE Dev）、高橋（UI/UX Designer）

## 2. 議題・背景

ユーザーテストおよびカスタマーサポートからのフィードバックに基づき、ショッピングカート内の商品を一括で削除・クリアできる「カートリセット機能」の追加に関する仕様策定およびタスクの切り出しを実施しました。

- **現状の課題:** 現行仕様では商品を1点ずつ削除する必要があり、大量アイテム追加後の全削除操作に手間がかかる。

## 3. 決定した仕様・要件

### フロントエンド (FE)

- **UI配置:** カート画面（商品一覧上部および合計金額エリア付近）に「カートを空にする」ボタンを配置。
- **誤操作防止モーダル:** ボタン押下時、ダイアログを表示（「カート内のすべての商品を削除しますか？」 / [キャンセル] [削除する]）。
- **表示更新:** 削除実行後、カート状態を即座に空にし、ヘッダーのカートバッジ表示を「0」へ更新。完了トースト「カートをクリアしました」を表示。

### バックエンド (BE)

- **新規API作成:** DELETE /api/v1/cart/items エンドポイントを新設。
- **処理:** セッションIDまたはログインユーザーIDに紐づくカート内全レコードの一括削除処理。
- **レスポンス:** 成功時 200 OK（空のカートオブジェクトを返却）。

### UI/UXデザイン

- **ボタンデザイン:** 誤操作を防ぎつつ、主アクション（購入手続き）を邪魔しないセカンダリボタン（赤枠または赤テキスト）とする。

## 5. 懸念点・メモ

- **ゲストユーザーのデータクリア範囲:** 非ログイン状態でのカートリセット時、Cookieおよびローカルストレージのクリア範囲についてフロントエンド側で要検証。
- **パフォーマンス最適化:** 大量商品追加時の一括削除処理でタイムアウトが発生しないよう、データベースのインデックスおよびクエリを最適化すること。
